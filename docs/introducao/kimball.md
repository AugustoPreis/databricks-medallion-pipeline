# Modelagem Dimensional (Ralph Kimball)

## O que é Modelagem Dimensional?

A **Modelagem Dimensional** é uma técnica de design de Data Warehouses criada por **Ralph Kimball**. Ela organiza os dados em dois tipos de tabelas:

- **Tabelas de Dimensão (Dim):** descrevem as entidades do negócio (quem, o quê, onde, quando)
- **Tabelas de Fato (Fato):** registram os eventos de negócio com métricas numéricas

O resultado é um **Schema Estrela** (Star Schema) ou **Schema Floco de Neve** (Snowflake Schema).

## Schema Estrela deste projeto

```
                  dim_tempo
                  (FK_TEMPO)
                      │
                      │
dim_produto ───── fato_vendas ────── dim_localidade
(FK_PRODUTO)          │               (FK_LOCALIDADE)
                      │
                  dim_cliente
                  (FK_CLIENTE)
```

### Tabela Fato: `fato_vendas`

| Coluna          | Tipo   | Descrição                                            |
| --------------- | ------ | ---------------------------------------------------- |
| `FK_TEMPO`      | Date   | Chave estrangeira → `dim_tempo.Data`                 |
| `FK_PRODUTO`    | Int    | Chave estrangeira → `dim_produto.SK_PRODUTO`         |
| `FK_CLIENTE`    | Int    | Chave estrangeira → `dim_cliente.SK_CLIENTE`         |
| `FK_LOCALIDADE` | Int    | Chave estrangeira → `dim_localidade.SK_LOCALIDADE`   |
| `QT_ITENS`      | Int    | Métrica: quantidade total de itens vendidos          |
| `VL_TOTAL`      | Double | Métrica: receita bruta (preço × quantidade)          |
| `VL_DESCONTO`   | Double | Métrica: total de descontos concedidos               |

**Grain (granularidade):** um registro por combinação de (dia, produto, cliente, localidade).

## Surrogate Keys (Chaves Substitutas)

As dimensões utilizam **Surrogate Keys** (SK) geradas automaticamente pelo banco de dados:

```sql
SK_PRODUTO bigint GENERATED BY DEFAULT AS IDENTITY
```

Vantagens das Surrogate Keys:

- Independência do sistema de origem (natural key pode mudar)
- Performance em joins (inteiro vs. string)
- Suporte a SCD (Slowly Changing Dimensions)

---

## SCD Tipo 1 (Slowly Changing Dimensions)

As dimensões deste projeto implementam **SCD Tipo 1**: quando um atributo de uma dimensão muda, o valor antigo é simplesmente **sobrescrito**.

Implementado via `MERGE INTO`:

```sql
MERGE INTO gold.dim_cliente AS d
USING cliente_relacional AS r
ON r.codigo_cliente = d.codigo_cliente

WHEN MATCHED AND (r.nome <> d.nome OR ...) THEN
    UPDATE SET nome = r.nome, ...

WHEN NOT MATCHED THEN
    INSERT (codigo_cliente, nome, ...)
    VALUES (r.codigo_cliente, r.nome, ...)
```

**Nota:** SCD Tipo 2 (histórico de mudanças) seria necessário se fosse preciso preservar o estado anterior dos atributos dimensionais.
